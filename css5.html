Overview

Positioning controls where elements appear on the page and how they interact with other elements. This lesson explains the normal document flow, the position property values, stacking contexts, and practical patterns for layout and UI components.

Normal flow

By default, elements participate in the normal document flow: block-level elements stack vertically, inline elements flow horizontally. Understanding normal flow is the foundation for using positioning without breaking layout unexpectedly.

/* normal flow examples */
header { display: block; }
p { display: block; margin: 1rem 0; }
span { display: inline; }
Tip: Try to rely on normal flow and modern layout systems (flexbox, grid) for most layouts; use positioning for overlays, small UI components, and exceptions.

Position property

The position property accepts several values. Each changes how an element is laid out and how offsets (top, right, bottom, left) are interpreted.

static

Default. Element follows normal flow; offsets have no effect.

relative

Element remains in normal flow but can be offset relative to its normal position. Offsetting does not affect surrounding elements' layout space.

absolute

Element is removed from normal flow and positioned relative to the nearest positioned ancestor (an ancestor with position other than static). If none exists, it is positioned relative to the initial containing block (usually the viewport).

fixed

Element is removed from flow and positioned relative to the viewport. It stays fixed during scrolling (unless inside a transformed ancestor in some browsers).

sticky

Hybrid: behaves like relative until a threshold is crossed, then becomes fixed relative to its nearest scrolling ancestor. Useful for headers and table-of-contents sidebars.

/* examples */
.box-relative { position: relative; top: 8px; left: 8px; }
.box-absolute { position: absolute; top: 16px; right: 16px; }
.box-fixed { position: fixed; bottom: 12px; right: 12px; }
.header-sticky { position: sticky; top: 0; }

Z-index and stacking context

z-index controls stacking order for positioned elements. Stacking contexts determine how z-index values are compared; new stacking contexts are created by certain properties (for example position with z-index, opacity less than 1, transform, filter, and mix-blend-mode).

/* stacking example */
.modal { position: fixed; z-index: 1000; }
.overlay { position: fixed; z-index: 900; }

/* transformed parent creates a new stacking context */
.parent { transform: translateZ(0); }
.child { position: absolute; z-index: 9999; /* z-index limited to parent's context */ }
Warning: Unexpected stacking issues often come from unintended stacking contexts (for example a parent with transform). Inspect computed styles in DevTools to debug.

Sticky and fixed

Fixed is great for persistent UI (toasts, sticky footers). Sticky is ideal for elements that should remain visible within a scroll container (table headers, side navigation).

/* sticky header */
.header {
  position: sticky;
  top: 0;
  z-index: 50;
  background: rgba(7,20,40,0.95);
}

/* fixed action button */
.fab {
  position: fixed;
  right: 16px;
  bottom: 16px;
  z-index: 1000;
}
Notes on sticky
  • Sticky only works within the scrollable ancestor; if the ancestor has overflow set, sticky behavior is relative to that container.
  • Ensure the sticky element's parent has enough height for the effect to be noticeable.

Transforms & positioning tricks

Transforms do not affect document flow but create new stacking contexts. Use transforms and translate for smoother animations and to center elements without affecting layout space.

/* centering with transform */
.centered {
  position: absolute;
  left: 50%;
  top: 50%;
  transform: translate(-50%, -50%);
}

/* hardware-accelerated animation */
.pop {
  transform: translateZ(0) scale(1);
  transition: transform 180ms ease;
}
.pop:hover { transform: translateZ(0) scale(1.03); }
Performance tip: Animate transforms and opacity where possible; avoid animating layout-triggering properties like width, height, top, or left for smoother rendering.

Best practices

  • Prefer modern layout systems (flexbox, grid) for most layout tasks; use positioning for overlays and small UI components.
  • Keep stacking contexts intentional; avoid creating unnecessary ones with transforms or opacity.
  • Use position: relative on a container to scope absolutely positioned children.
  • Test sticky and fixed elements on mobile; some mobile browsers handle fixed positioning differently.
  • Use translate() for centering and animations to avoid layout thrashing.

Examples — practical snippets

Scoped absolute positioning

.card {
  position: relative; /* establishes containing block for absolute children */
  padding: 16px;
}
.card .badge {
  position: absolute;
  top: 12px;
  right: 12px;
  background: var(--accent);
  color: #fff;
  padding: 6px 8px;
  border-radius: 6px;
}

Sticky table header

.table-wrapper { max-height: 60vh; overflow: auto; }
.table-wrapper thead th {
  position: sticky;
  top: 0;
  background: #071428;
  z-index: 10;
}

Centered modal

.modal {
  position: fixed;
  left: 50%;
  top: 50%;
  transform: translate(-50%, -50%);
  width: min(90%, 720px);
  background: #071428;
  padding: 20px;
  border-radius: 10px;
  z-index: 1000;
}
.overlay {
  position: fixed;
  inset: 0;
  background: rgba(0,0,0,0.6);
  z-index: 900;
}
Practice: Build a small demo with a card that has an absolutely positioned badge, a sticky sidebar, and a centered modal to see how positioning interacts with flow and stacking.
