CSS Lesson 8 — Transforms, Effects, and Motion

Estimated time: 35–55 minutes · Level: Intermediate
Back to Lessons

Overview

This lesson covers CSS transforms, visual effects, and motion techniques. You will learn how to manipulate elements in 2D and 3D, apply filters and blend modes, create smooth transitions and keyframe animations, and apply motion responsibly for performance and accessibility.

Transforms and Filters

Transforms change the coordinate space of an element without affecting document flow. Use transforms for positioning, scaling, rotating, and 3D effects. Transforms are GPU-friendly and ideal for animations.

Common transform functions

/* 2D transforms */
.transform-translate { transform: translate(20px, 10px); }
.transform-scale { transform: scale(1.1); }
.transform-rotate { transform: rotate(12deg); }

/* 3D transforms */
.transform-3d { transform: perspective(800px) rotateY(18deg); }

/* combine transforms */
.card:hover { transform: translateY(-6px) rotateX(2deg) scale(1.02); }

Filters apply image-like effects to elements. Use filters for subtle visual polish and to avoid extra image assets.

Common filter functions

/* filters */
.blur { filter: blur(6px); }
.grayscale { filter: grayscale(100%); }
.contrast { filter: contrast(1.15) saturate(1.05); }

/* multiple filters */
.photo { filter: saturate(1.1) contrast(1.05) drop-shadow(0 6px 12px rgba(0,0,0,0.45)); }
Tip: Prefer transforms and opacity for animations. Filters can be expensive on some devices so use them sparingly and test performance.

Transitions and Animations

Transitions provide simple, declarative interpolation between two states. Use transitions for hover, focus, and state changes. Keyframe animations enable more complex sequences and looping motion.

Transitions

/* transition example */
.button {
  transition: background-color 180ms ease, transform 220ms cubic-bezier(.2,.9,.2,1);
}
.button:hover {
  background-color: #0088dd;
  transform: translateY(-4px);
}

Keyframe animations

/* keyframes */
@keyframes float {
  0% { transform: translateY(0); }
  50% { transform: translateY(-8px); }
  100% { transform: translateY(0); }
}

/* apply animation */
.icon-float {
  animation: float 3s ease-in-out infinite;
}

Animation properties to control behavior:

  • animation-duration
  • animation-timing-function
  • animation-delay
  • animation-iteration-count
  • animation-direction
  • animation-fill-mode
Motion design pattern

Use short, subtle transitions for micro-interactions and longer, eased keyframes for decorative motion. Keep motion meaningful and avoid gratuitous movement.

Responsive Motion and Layout Considerations

Motion must adapt to different screen sizes and input methods. Use media queries and feature detection to tailor effects. Avoid absolute positioning that breaks layout when animating size or position.

Responsive techniques

/* reduce motion on small screens */
@media (max-width: 600px) {
  .hero-animate { animation: none; transform: none; }
}

/* respect prefers-reduced-motion */
@media (prefers-reduced-motion: reduce) {
  .icon-float, .button { transition: none; animation: none; }
}

Layout-friendly motion uses transforms and opacity so layout does not reflow during animation. When you must animate layout properties, keep durations short and test for jank.

Performance and Accessibility

Design motion that is performant and inclusive. Prioritize animations that run on the compositor thread and avoid layout-triggering properties. Respect user preferences for reduced motion and ensure motion does not cause disorientation.

Performance checklist

  • Animate transform and opacity where possible.
  • Avoid animating width, height, top, or left for frequent animations.
  • Use will-change sparingly to hint the browser about upcoming animations.
  • Test on low-end devices and measure frame rates in DevTools.

Accessibility checklist

  • Honor prefers-reduced-motion and provide non-animated alternatives.
  • Do not rely on motion alone to convey information. Provide text or ARIA updates when motion indicates state changes.
  • Keep motion short and avoid rapid flashing that could trigger seizures.
/* safe hint for upcoming transform */
.card {
  will-change: transform, opacity;
}

/* reduced motion fallback */
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.001ms !important; transition-duration: 0.001ms !important; }
}

Examples and Sources

Subtle hover lift

.card {
  transition: transform 220ms cubic-bezier(.2,.9,.2,1), box-shadow 220ms ease;
  transform-origin: center;
}
.card:hover {
  transform: translateY(-8px) scale(1.01);
  box-shadow: 0 18px 40px rgba(0,0,0,0.45);
}

Accessible toast animation

@keyframes slideIn {
  from { transform: translateY(12px); opacity: 0; }
  to { transform: translateY(0); opacity: 1; }
}

.toast {
  animation: slideIn 240ms cubic-bezier(.2,.9,.2,1) both;
}

/* respect reduced motion */
@media (prefers-reduced-motion: reduce) {
  .toast { animation: none; opacity: 1; transform: none; }
}

3D card tilt

.card-3d {
  perspective: 900px;
}
.card-3d .inner {
  transform-style: preserve-3d;
  transition: transform 300ms ease;
}
.card-3d:hover .inner {
  transform: rotateX(6deg) rotateY(-8deg);
}
Practice

Create three small demos: a hover-lift card, a looping decorative icon using keyframes, and a toast that respects reduced motion. Test each on desktop and mobile.

Checklist
  • Does motion use transform or opacity?
  • Is performance acceptable on low-end devices?
  • Does the UI respect prefers-reduced-motion?
  • Is information conveyed by motion also available as text?
