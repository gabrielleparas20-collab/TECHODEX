Overview

Responsive design ensures interfaces adapt to different screen sizes, input methods, and user preferences. This lesson covers the practical tools and patterns: fluid units, media queries, container queries, responsive images, and how to respect accessibility and performance while building flexible layouts.

Core principles

  • Mobile first — design for small screens first, then enhance for larger viewports.
  • Progressive enhancement — provide a usable baseline and layer improvements.
  • Fluidity — prefer flexible units and layouts that adapt rather than fixed breakpoints only.
  • Performance — load only what’s necessary for the current context.
Rule: Start with a simple, readable layout and add complexity only where it improves the experience.

Responsive units and viewport

Choose units that scale well across devices:

  • rem — root-relative, respects user font-size settings.
  • em — relative to the current element's font-size.
  • % — relative to parent dimensions.
  • vw / vh — viewport width/height; use carefully for text to avoid overly large/small sizes.
  • vmin / vmax — based on smaller/larger viewport dimension.
  • fr — grid fractional unit for flexible tracks.
/* fluid typography using clamp */
h1 {
  font-size: clamp(1.5rem, 2.5vw + 1rem, 3rem);
}

/* layout using rem and percent */
.container {
  padding: 1rem;
  max-width: 1200px;
  margin: 0 auto;
}
Tip: Use rem for spacing and type to respect user preferences; use viewport units for decorative, non-critical sizing.

Media queries and breakpoints

Media queries let you apply styles based on viewport characteristics. Favor a mobile-first approach: write base styles for small screens and add queries for larger viewports.

Basic syntax

/* mobile-first: add rules for larger screens */
@media (min-width: 640px) {
  .grid { grid-template-columns: repeat(2, 1fr); }
}

@media (min-width: 1024px) {
  .grid { grid-template-columns: repeat(3, 1fr); }
}

Choosing breakpoints

Prefer content-driven breakpoints rather than device-specific ones. Inspect where the layout breaks and add a breakpoint there.

Media features

/* orientation */
@media (orientation: landscape) { ... }

/* reduced motion preference */
@media (prefers-reduced-motion: reduce) { ... }

/* high-resolution images */
@media (min-resolution: 2dppx) { ... }
Pattern 
/* base (mobile) */
.nav { display: block; }

/* tablet and up */
@media (min-width: 768px) {
  .nav { display: flex; gap: 1rem; }
}

Container queries & feature queries

Container queries allow components to adapt to the size of their container rather than the viewport. Use @container for truly modular, reusable components. Use @supports to feature-detect CSS capabilities.

/* enable container sizing on the parent */
.card {
  container-type: inline-size;
}

/* query based on container width */
@container (min-width: 360px) {
  .card { display: flex; gap: 1rem; }
}

/* feature query */
@supports (display: grid) {
  .layout { display: grid; }
}
Browser support: Container queries are supported in modern browsers; use feature detection and fallbacks for older browsers.

Accessibility & user preferences

Respect user settings and ensure responsive changes do not break accessibility.

  • Honor prefers-reduced-motion and provide non-animated alternatives.
  • Respect prefers-color-scheme for light/dark themes and provide readable contrast in both modes.
  • Ensure focus order and keyboard navigation remain logical across breakpoints.
  • Test with screen readers and keyboard-only navigation at multiple viewport sizes.
/* reduced motion */
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}

/* dark mode */
@media (prefers-color-scheme: dark) {
  :root { --bg: #071428; --text: #eaf6ff; }
}
Tip: When changing layout order visually (grid/flex reordering), keep DOM order meaningful for keyboard and assistive tech.

Examples — practical snippets

Mobile-first layout with breakpoints

/* base (mobile) */
.container {
  padding: 1rem;
  display: block;
}

/* tablet */
@media (min-width: 768px) {
  .container { display: grid; grid-template-columns: 1fr 320px; gap: 1.25rem; }
}

/* desktop */
@media (min-width: 1200px) {
  .container { max-width: 1200px; margin: 0 auto; }
}

Fluid card width using clamp

.card {
  width: clamp(220px, 30vw, 420px);
  padding: 1rem;
  box-sizing: border-box;
}

Container query for a component

.card {
  container-type: inline-size;
  padding: 1rem;
}

@container (min-width: 420px) {
  .card { display: flex; gap: 1rem; align-items: center; }
}
Practice: Convert a fixed-width layout into a mobile-first responsive layout. Replace fixed breakpoints with content-driven ones and add a container query for a reusable card component.
