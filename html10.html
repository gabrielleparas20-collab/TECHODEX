Overview

This lesson gathers advanced HTML patterns and practical best practices you’ll use when building real sites: progressive enhancement, performance-minded markup, basic security considerations, and testing/debugging workflows. These practices help your pages remain robust, fast, and maintainable.

Progressive enhancement

Start with a solid HTML baseline that works without JavaScript, then layer on CSS and JavaScript. This ensures content is accessible and functional in constrained environments and improves resilience.

Principles

  • Deliver meaningful content in plain HTML first.
  • Add CSS for presentation and JavaScript for enhanced interactions.
  • Feature-detect APIs and provide fallbacks when unavailable.
Pattern 
<button class="menu-toggle" aria-expanded="false">Menu</button>
<nav class="main-nav" hidden>...</nav>

<script>
  const btn = document.querySelector('.menu-toggle');
  const nav = document.querySelector('.main-nav');
  btn.addEventListener('click', () => {
    const expanded = btn.getAttribute('aria-expanded') === 'true';
    btn.setAttribute('aria-expanded', String(!expanded));
    nav.hidden = expanded;
  });
</script>

Performance tips

Small HTML choices affect load time and perceived performance. Optimize markup and assets to reduce blocking and improve first meaningful paint.

Practical rules

  • Include the viewport meta tag and critical metadata in the head.
  • Defer nonessential scripts; place critical CSS inline or load it early.
  • Use responsive images (srcset, sizes) and modern image formats (WebP/AVIF) where supported.
  • Prefer semantic elements to reduce extra wrapper markup.
Responsive image 
<img src="hero-800.jpg"
     srcset="hero-400.jpg 400w, hero-800.jpg 800w, hero-1200.jpg 1200w"
     sizes="(max-width:600px) 100vw, 800px"
     alt="Project screenshot">

Security basics

HTML interacts with other layers; follow simple rules to reduce common risks.

  • Never embed untrusted HTML; sanitize server-side before rendering.
  • Use rel="noopener noreferrer" with target="_blank".
  • Prefer HTTPS for all pages and assets to protect integrity and privacy.
  • Avoid exposing secrets in markup or data attributes.
Example: safe external link 
<a href="https://external.example" target="_blank" rel="noopener noreferrer">External site</a>

Testing & debugging

Adopt a simple workflow to catch issues early: validate markup, test accessibility, and inspect network and rendering behavior.

Checklist

  • Run HTML validation (W3C validator) for structural issues.
  • Use browser DevTools to inspect network, layout, and console errors.
  • Test keyboard navigation and screen-reader basics for accessibility.
  • Check pages on multiple viewport sizes and devices (or emulators).
Quick DevTools tip 
Open DevTools → Network tab → Reload page to see blocking resources and load times.

Examples — practical snippets

Minimal accessible modal (pattern)

<button id="open" aria-haspopup="dialog" aria-controls="modal">Open</button>
<div id="modal" role="dialog" aria-modal="true" hidden>
  <h2 id="modalTitle">Dialog</h2>
  <button id="close">Close</button>
</div>

<script>
const open = document.getElementById('open');
const close = document.getElementById('close');
const modal = document.getElementById('modal');
open.addEventListener('click', () => modal.hidden = false);
close.addEventListener('click', () => modal.hidden = true);
</script>

Lightweight lazy-load pattern

<img loading="lazy" src="thumb.jpg" data-src="hero.jpg" alt="...">

<script>
if ('loading' in HTMLImageElement.prototype) {
  document.querySelectorAll('img[loading="lazy"]').forEach(img => {
    img.src = img.dataset.src || img.src;
  });
}
</script>
