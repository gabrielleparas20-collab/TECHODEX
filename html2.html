Lesson 2 — Text and Headings

Estimated time: 20–35 minutes · Level: Beginner

Overview

This lesson focuses on text content and headings: how to structure text, when to use each heading level, the difference between inline and block elements, and practical guidelines for readable, accessible content. Proper text structure improves scanning, accessibility, and SEO.

Headings

Headings create the document outline. Use a single <h1> for the page title and nested headings (<h2>, <h3>, etc.) to represent subsections. Headings should reflect content hierarchy, not visual size.

Best practices

  • Use one <h1> per page for the main title.
  • Choose heading levels to reflect structure, not appearance.
  • Keep headings concise and descriptive to help scanning and navigation.
Example outline 
<h1>Course: Intro to Web</h1>
<h2>Module 1: HTML Basics</h2>
<h3>Lesson 1: Document structure</h3>
<h3>Lesson 2: Text and headings</h3>
<h2>Module 2: CSS Basics</h2>

Inline vs block elements

Elements are either inline or block-level. Block elements (for example <div>, <p>, <h1>) start on a new line and can contain other blocks and inline elements. Inline elements (for example <span>, <a>, <strong>) flow within text and do not start new lines.

When to use each

  • Use block elements for structural pieces and paragraphs.
  • Use inline elements for styling or marking up small runs of text inside blocks.
Inline vs block example 
<p>This is a paragraph with an <strong>inline emphasis</strong> and a <span class="note">small note</span> inside it.</p>

<div class="card">
  <h2>Card title</h2>
  <p>Card content here.</p>
</div>

Text formatting and semantics

Prefer semantic elements for meaning: <strong> for strong importance, <em> for emphasis, <mark> for highlighted text, and <code> for inline code. Avoid using elements purely for visual styling (for example using <b> or <i> without semantic reason).

Examples

<p>Use <strong>important</strong> to indicate strong importance.</p>
<p>Use <em>emphasis</em> for stressed text.</p>
<p>Inline code: <code>console.log('hello')</code></p>
Accessibility note: Screen readers treat semantic tags differently; choose tags that match meaning rather than appearance.

Structure guidelines

Keep content scannable: short paragraphs, descriptive headings, and lists for grouped items. Use headings to create a clear outline and avoid skipping heading levels arbitrarily (for example jumping from <h1> to <h4> without intermediate levels).

Readable paragraphs

  • Limit paragraph length for web reading (2–4 short sentences).
  • Use lists for steps or related items.
  • Use subheadings to break long content into digestible sections.

Examples — practical snippets

Article structure

<article>
  <h2>How to write accessible headings</h2>
  <p>Short intro paragraph.</p>
  <h3>Why headings matter</h3>
  <p>Explanation and examples.</p>
</article>

Inline formatting in context

<p>To install, run <code>npm install techodex</code> in your terminal.</p>
<p>This is <strong>important</strong> and should be noted.</p>
Tip: When converting a document to HTML, first create a clear heading outline on paper or in a text editor, then map each heading to the appropriate <h#> level.

Summary

Headings and text structure are the backbone of readable, accessible web content. Use semantic headings to create a logical outline, prefer semantic inline elements for meaning, and keep paragraphs short and scannable. These practices improve usability, accessibility, and search relevance.
