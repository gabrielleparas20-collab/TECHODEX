Lesson 4 — Lists and Tables

Estimated time: 25–40 minutes · Level: Beginner
Back to Lesson 3
Overview Lists List types & nesting Tables Tables and accessibility Examples Sources

Overview

This lesson covers lists and tables: when to use each, how to structure them semantically, nesting rules, and accessibility considerations. Lists are for grouped items; tables are for tabular data only.

Lists

Use lists to group related items. Choose the correct list type for meaning:

  • Unordered list (<ul>) for items without a required order.
  • Ordered list (<ol>) for sequences or steps.
  • Description list (<dl>) for name/value pairs or term/definition pairs.

Structure

Each list item uses <li>. Description lists use <dt> (term) and <dd> (description).

<ul>
  <li>Apples</li>
  <li>Bananas</li>
</ul>

<ol>
  <li>Preheat oven</li>
  <li>Mix ingredients</li>
</ol>

<dl>
  <dt>HTML</dt>
  <dd>HyperText Markup Language</dd>
</dl>
Tip: Avoid using lists purely for visual layout (for example to create columns of links). Use CSS for layout and keep lists for semantic grouping.

List types and nesting

Nesting lists is allowed; keep nesting shallow for readability. Use ordered lists for steps and unordered lists for collections. Use CSS counters if you need custom numbering styles.

<ol>
  <li>Step one
    <ol>
      <li>Sub-step A</li>
      <li>Sub-step B</li>
    </ol>
  </li>
  <li>Step two</li>
</ol>
When not to use lists

Do not use lists to group unrelated layout elements; prefer semantic containers and CSS for layout control.

Tables

Use tables only for tabular data — information that fits naturally into rows and columns. Do not use tables for page layout.

Basic table structure

Use <table> with optional <caption>, a header row in <thead>, body rows in <tbody>, and optional footer in <tfoot>. Use <th> for header cells and <td> for data cells.

<table>
  <caption>Monthly sales (USD)</caption>
  <thead>
    <tr>
      <th>Month</th>
      <th>Sales</th>
    </tr>
  </thead>
  <tbody>
    <tr><td>January</td><td>10,000</td></tr>
    <tr><td>February</td><td>12,500</td></tr>
  </tbody>
</table>
Tip: Always include a <caption> for context and use header cells (<th>) to describe columns or rows.

Tables and accessibility

Accessible tables use clear headers and, when necessary, scope attributes (scope="col" or scope="row") or id/headers associations for complex tables. Provide a caption and, for very complex tables, a summary or long description via nearby text or aria-describedby.

<table>
  <caption>Quarterly revenue</caption>
  <thead>
    <tr>
      <th scope="col">Quarter</th>
      <th scope="col">Revenue</th>
    </tr>
  </thead>
  <tbody>
    <tr><td>Q1</td><td>$50,000</td></tr>
  </tbody>
</table>
Complex tables

For tables with multi-row headers or merged cells, use id on header cells and headers on data cells to explicitly associate them for assistive tech.

Examples — practical snippets

Shopping list (unordered)

<ul>
  <li>Milk</li>
  <li>Bread</li>
  <li>Eggs</li>
</ul>

Recipe steps (ordered)

<ol>
  <li>Preheat oven to 180°C.</li>
  <li>Mix dry ingredients.</li>
  <li>Bake for 25 minutes.</li>
</ol>

Data table with caption

<table>
  <caption>Top contributors</caption>
  <thead>
    <tr><th>Name</th><th>Contributions</th></tr>
  </thead>
  <tbody>
    <tr><td>Alex</td><td>42</td></tr>
    <tr><td>Sam</td><td>37</td></tr>
  </tbody>
</table>
Practice tip: Convert a list of items from a plain text file into an HTML list and a small CSV into a table to practice structure and semantics.

Summary

Use lists for grouped items and tables for true tabular data. Keep markup semantic, include captions and headers for tables, and ensure accessibility with proper attributes and descriptions. Avoid using tables for layout and avoid using lists for purely visual grouping.
