Lesson 5 — Forms and Inputs

Estimated time: 30–45 minutes · Level: Beginner
Back to Lesson 4

Overview

Forms collect user input. This lesson covers the semantic structure of forms, common input types, labeling and accessibility, client-side validation basics, and security/privacy considerations. Well-structured forms improve usability and reduce errors.

Form structure

The <form> element wraps controls and defines submission behavior via action and method. Use fieldsets and legends to group related controls.

<form action="/subscribe" method="post">
  <fieldset>
    <legend>Contact details</legend>
    <label for="name">Name</label>
    <input id="name" name="name" type="text" required>
  </fieldset>
  <button type="submit">Submit</button>
</form>
Tip: Use method="post" for actions that change server state or submit sensitive data.

Input types

HTML provides many input types that improve UX and enable built-in validation: text, email, tel, number, url, password, date, checkbox, radio, file, and more.

<input type="text" name="username" required>
<input type="email" name="email" required>
<input type="tel" name="phone">
<input type="number" name="quantity" min="1" max="10">
<input type="checkbox" id="agree" name="agree">
<input type="file" name="attachment" accept=".pdf,.jpg">
Why types matter

Using type="email" triggers email-specific keyboards on mobile and enables browser validation for email format.

Labels and accessibility

Always associate labels with inputs using for and id, or wrap the input inside the label. Use aria-describedby for additional help text and aria-invalid to indicate validation state.

<label for="email">Email address</label>
<input id="email" name="email" type="email" aria-describedby="emailHelp" required>
<div id="emailHelp">We will never share your email.</div>
Tip: For groups of radios or checkboxes, use a fieldset with a legend to provide context for assistive technologies.

Validation

Browsers provide basic validation for certain input types and attributes (required, min, max, pattern). Use client-side validation for immediate feedback, but always validate on the server as well.

<input type="text" name="zip" pattern="\\d{5}" title="Five digit ZIP code">

UX note

Show clear, inline error messages and keep focus on the first invalid control to help users correct mistakes quickly.

Security and privacy

  • Never rely solely on client-side validation; validate and sanitize on the server.
  • Use HTTPS for forms that transmit sensitive data.
  • Limit file upload types and sizes; scan or validate uploads server-side.
  • Minimize data collection and explain why you collect each field.
Privacy tip: Add a short privacy note near sensitive fields (for example, why you need an email) to build trust.

Examples — practical snippets

Contact form

<form action="/contact" method="post">
  <label for="name">Full name</label>
  <input id="name" name="name" type="text" required>

  <label for="email">Email</label>
  <input id="email" name="email" type="email" required>

  <label for="message">Message</label>
  <textarea id="message" name="message" rows="6" required></textarea>

  <button type="submit">Send</button>
</form>

Login form (minimal)

<form action="/login" method="post">
  <label for="user">Username</label>
  <input id="user" name="user" type="text" required>

  <label for="pass">Password</label>
  <input id="pass" name="pass" type="password" required>

  <button type="submit">Log in</button>
</form>
Practice tip: Build a small contact form and test it in your browser. Inspect the network request to see the form payload and experiment with client-side validation attributes.

Summary

Forms are essential for interaction. Use semantic structure, label every control, choose appropriate input types, provide clear validation feedback, and always validate on the server. Prioritize security and privacy when collecting user data.
