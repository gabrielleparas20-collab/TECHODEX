Overview

Semantic HTML uses elements that convey meaning about the content they contain. Using semantic elements improves accessibility, search engine understanding, and maintainability. This lesson explains common landmark elements, when to prefer them over generic containers, and how to combine semantic markup with ARIA when needed.

Landmark elements

Landmark elements define the major regions of a page. Use them to create a clear document outline and to help assistive technologies navigate content.

  • <header> — introductory content or site/page header.
  • <nav> — primary navigation links.
  • <main> — the main content of the document (one per page).
  • <article> — self-contained content that could be syndicated.
  • <section> — thematic grouping of content, typically with a heading.
  • <aside> — tangential content such as sidebars or pull quotes.
  • <footer> — footer for a page or section.
Simple page skeleton 
<header>
  <h1>Site title</h1>
  <nav>...</nav>
</header>

<main>
  <article>
    <h2>Article title</h2>
    <p>Article content...</p>
  </article>

  <aside>
    <h3>Related</h3>
    <p>Sidebar content...</p>
  </aside>
</main>

<footer>...</footer>

When to use semantic elements

Prefer semantic elements when the element's role is clear. Use generic <div> only when no semantic element fits. Semantic markup helps:

  • Screen readers and assistive tech to navigate the page.
  • Search engines to understand page structure and content.
  • Developers to maintain and reason about the codebase.
Rule of thumb: If a container has a clear role (navigation, main content, article, sidebar), use the corresponding semantic element.

ARIA basics

ARIA (Accessible Rich Internet Applications) provides attributes to enhance accessibility when native semantics are insufficient. Use ARIA to fill gaps, not to replace semantic HTML.

Common ARIA attributes

  • role — explicitly defines an element's role (for example role="navigation").
  • aria-label — provides an accessible name when visible text is not available.
  • aria-labelledby — references an element that labels the current element.
  • aria-describedby — references an element that describes the current element.
  • aria-hidden="true" — hides decorative content from assistive tech.
Use ARIA only when needed 
<nav aria-label="Primary navigation">
  <ul>...</ul>
</nav>

<div role="dialog" aria-labelledby="dialogTitle">
  <h2 id="dialogTitle">Dialog title</h2>
  ...
</div>
Warning: Misusing ARIA can reduce accessibility. Always prefer native semantic elements first.

Practical patterns

Header + nav pattern

<header>
  <div class="brand"><h1>Site</h1></div>
  <nav aria-label="Main">...</nav>
</header>

Article with related aside

<main>
  <article>
    <h2>Article title</h2>
    <p>Content...</p>
  </article>

  <aside aria-label="Related resources">
    <h3>Related</h3>
    <ul>...</ul>
  </aside>
</main>

Landmark roles for single-page apps

In dynamic apps, ensure landmarks remain present and update content inside them rather than removing landmarks entirely. Use aria-live for important dynamic updates.

Examples

Blog post layout

<article>
  <header>
    <h1>Post title</h1>
    <p>By Author — Date</p>
  </header>

  <section>
    <h2>Introduction</h2>
    <p>...</p>
  </section>

  <footer>
    <p>Tags: ...</p>
  </footer>
</article>

Accessible navigation

<nav aria-label="Primary">
  <ul>
    <li><a href="/home">Home</a></li>
    <li><a href="/about">About</a></li>
  </ul>
</nav>
Practice: Review an existing page and replace generic <div> containers with semantic elements where appropriate.

Summary

Semantic HTML clarifies the role of content for users, assistive technologies, and search engines. Use landmark elements for structure, prefer native semantics over ARIA when possible, and apply ARIA only to fill gaps. Small semantic choices compound into a more accessible, maintainable site.
